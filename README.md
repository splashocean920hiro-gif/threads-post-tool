# Threads運用ツール

Threadsの投稿を「集める → 作る → 予約する → 自動で投稿する → 結果を見る」まで一つにしたツールです。
Railwayに**自分専用の環境**として立てて使います。

APIキーやアクセストークンは、あなたが立てた環境の中だけに保存されます。
作者を含め、他の人のサーバーには一切送られません。

---

## できること

- **伸びた投稿を自動で集める**（Chrome拡張機能。あなたがThreadsを見ているあいだに裏で収集）
- **集めた投稿をお手本に、1日分の投稿をまとめて生成**（Gemini）
- **指定した時刻に自動投稿**（本文＋リプライ2本のツリー投稿）
- **インプレッションを自動で回収**して、伸びた投稿が分かる
- **1つのログインで複数のThreadsアカウントを管理**（担当キーワードで参考投稿を自動振り分け）

---

## デプロイ後にやること

1. 発行されたURLを開き、**新規登録**でIDとパスワードを作る（8文字以上）
2. 左サイドバーの「＋」で**Threadsアカウントを追加**
3. 「データ関連 → API設定」で登録する
   - **Geminiのアクセスキー**（Google AI Studio で取得。無料枠で足ります）
   - **Threadsのアクセストークン**（Meta for Developers で取得）
   - **担当キーワード**（このアカウント用に集めたい言葉。1行に1つ）
4. 「初期設定・拡張機能」から**拡張機能をダウンロード**して Chrome に入れる
   - あなた専用の設定が入った状態でダウンロードされます。URLやキーの入力は不要です
5. 「データ関連 → API設定 → アカウント復旧」で**秘密の質問を設定**
   - パスワードを忘れたときに自分で再設定できるようになります

## 仕組み

| サービス | 役割 |
|---|---|
| **web** | 画面とAPI。SQLiteのDBは Volume の `/data` に置く |
| **cron** | 5分ごとに web の `/api/cron/run-due` を叩き、期限が来た予約を投稿する |

Railwayの Volume は1つのサービスにしか付けられないため、cron から直接DBは読めません。
そのため cron は HTTP で web を呼ぶ形にしています。

**Volume を `/data` にマウントしていないと、再デプロイのたびにデータが消えます。**
テンプレートから作った場合は設定済みです。

---

## 環境変数

テンプレートから作った場合は、すべて自動で設定されます。手で入れるものはありません。

| 変数 | 用途 |
|---|---|
| `SECRET_KEY` | セッションの署名鍵。**変えると全員ログアウトになります** |
| `CRON_SHARED_KEY` | cron が web を呼ぶときの合言葉。web と cron で同じ値にします |
| `DB_PATH` | `/data/threads.db` 固定 |
| `ARCHIVE_URL` | cron 側だけ。web のURL |
| `PUBLIC_BASE_URL` | 任意。独自ドメインを使う場合だけ設定します |

以下は通常設定しません。

| 変数 | 用途 |
|---|---|
| `INGEST_SHARED_KEY` | 旧バージョンからの移行用。新規環境では設定しないでください |
| `APP_PASSWORD` | 旧バージョンからの移行用。設定すると初期ユーザーが作られます |
| `FLASK_DEBUG` | ローカル開発でだけ `1` にします。**公開環境では絶対に設定しないでください** |
| `THREADS_API_BASE` | ローカル検証でスタブに向ける用 |

## 困ったとき

**予約した投稿が流れない**
- Threadsのアクセストークンの期限が切れていないか確認してください（約60日で切れます）
- cron サービスのログに `status=200` が5分おきに出ているか確認してください

**投稿が集まらない**
- 拡張機能の「アクセストークン」が設定されているか
- 担当キーワードが登録されているか（未設定だと「未分類」に入ります）
- しきい値が高すぎないか

**パスワードを忘れた**
- ログイン画面の「パスワードを忘れた方」から、秘密の質問で再設定できます
- 秘密の質問も未設定の場合は、Railwayのシェルから再設定できます
  ```
  railway ssh --project <id> --environment production --service <service> \
    -- python reset_password.py <ユーザーID>
  ```

**画面がおかしい / エラーが出る**
- エラーの文章をそのままAIに貼って「原因と直し方を教えて」と聞くのが早いです
- このコードは公開されているので、AIに読ませて直させることができます

## ローカルで動かす

```
pip install -r requirements.txt
DB_PATH=./data/threads.db SECRET_KEY=dev COOKIE_INSECURE=1 python app.py
```

`COOKIE_INSECURE=1` は http で動かすために必要です（本番では絶対に設定しないでください）。

---

## 注意

- 集めた投稿は、投稿の「型」を研究するための材料です。本文の転載・再公開はしないでください
- Threads / Meta / Google の各サービスは、それぞれの規約に従って利用してください
- 拡張機能は、誰でも見られる投稿の情報を読むだけです。投稿・いいね・フォローなどアカウントを操作する動作は含まれていません
